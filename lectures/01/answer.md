### 質問と回答の比較

「LoRAとは何ですか？」には、元のモデルを固定し、低ランク行列による追加パラメータだけを学習する手法という説明が返った。ただし、回答中の「学習すべきデータ量が劇的に減る」という説明は、学習するパラメータ数が減ることと、必要なデータ量が減ることを混同している。一般用語の回答も、そのまま正しいとは判断できない。

「AIE2026の講座の宿題にある『3レベル』とは何ですか？」には、「初級・基礎編」「中級・応用編」「上級・発展編」という一般的な難易度の説明が返った。モデルは冒頭で講座を「想定」と断り、末尾で資料の追加を求めていたが、途中にはこの講座の資料にない課題例や到達目標を挙げていた。

`data/glossary.json` の `homework-levels` は「基礎（講義内容の確認）」「実装（自分でコードを書く）」「発展（調査や試行）」で、どれか1つに取り組めば完了としている。モデルの回答から、この講座の正式な区分や提出条件は確認できない。講座固有の質問には、資料を渡すか参照できる仕組みが必要だと分かった。

## 宿題

- 取り組んだレベル：**実装**
- 内容：`app/ask.py` を改修し、会話履歴を保ったまま続けて質問できる `--chat` を追加した。

### 実装したこと

SDK の `client.chats.create(model=MODEL)` でセッションを作成し、同じセッションの `send_message()` を繰り返し呼ぶ。履歴を保持する範囲は起動中のプロセス内で、ファイルには保存しない。

`/exit`、`/quit`、EOF、Ctrl-C で終了し、空行は送信しない。対話中の API エラーは説明を表示して次の入力を受け付ける。質問を引数で渡す既存の単発モードと、質問省略時の既定質問も維持した。

トークン数のメタデータが欠けた場合は「取得不可」と表示し、実測値の0と区別する。API エラーの詳細に認証情報が含まれる可能性があるため、HTTP ステータスに応じた説明だけを表示する。

### 再実行の手順

Python 3.12 と uv を用意し、`GEMINI_API_KEY` を環境変数に設定する。Nix を使う場合は、先に `nix develop` を実行する。

```bash
uv sync --frozen
uv run pytest -q
uv run python -m app.ask "LoRAとは何ですか？"
uv run python -m app.ask "AIE2026の講座の宿題にある「3レベル」とは何ですか？"
uv run python -m app.ask --chat
```

対話モードでは次を順に入力する。

```text
私の好きなプログラミング言語はRustです。覚えてください。
私の好きなプログラミング言語は何ですか？
/exit
```

続いて、履歴のない別プロセスで同じ質問をする。

```bash
uv run python -m app.ask "私の好きなプログラミング言語は何ですか？"
```

今回の API 実測では、依存導入済みの仮想環境の `.venv/bin/python` を使って上記の `app.ask` を実行した。

### 結果

対話の2回目には「あなたの好きなプログラミング言語は Rust です！」と回答した。別プロセスの単発実行では、好きな言語は分からないと回答した。どちらも終了コード0であり、対話は `/exit` で正常終了した。

対話2回目の入力は77トークンで、同じ質問を単発で送った場合の10トークンより多かった。SDK が過去の発言と回答も後続リクエストに含めるため、会話を続けると入力トークンが増えることを実測で確認できた。この1例だけで、長い会話すべての記憶精度を保証するものではない。

API キーなしの自動テストは **37件成功**。通信部分をモックし、SDK が2回目のリクエストに user / model 双方の履歴を含めること、単発モードで履歴を共有しないこと、API エラー、トークン数の欠損と0、空の応答、終了操作を確認した。実 API では上の5応答を取得し、単体テストとは別に動作を確認した。

ローカル環境用に `flake.nix` と `flake.lock` も追加した。Python 3.12、uv、Git、GitHub CLI を用意でき、講座の Python 依存は `uv.lock` の固定版を使う。

### 気づきと制約

当初は Codex の実行プロセスに `GEMINI_API_KEY` が渡っておらず、API 呼び出し前に終了した。環境変数の引き継ぎを確認した後、実 API の検証を完了した。キーが手元のシェルで設定されていることと、子プロセスから読めることは別に確認する必要があった。

AI がコードを生成しただけでは、履歴を送れているかも、モデルが履歴を使って答えるかも分からない。SDK の送信内容を確認するテストと、実際の連続質問の両方が役立った。

Codespaces の新規作成と Copilot の操作は未検証。今回提出するのは、ローカルで実装・検証した会話機能であり、複数モデルの応答時間比較を行う発展課題は実施していない。
